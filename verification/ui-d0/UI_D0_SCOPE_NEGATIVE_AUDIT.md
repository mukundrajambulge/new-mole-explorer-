# Mole Explorer UI-D0 Scope-Negative Audit

## Boundary

This worktree starts exactly at `mole-explorer-docking-d2-accepted-2026-09-20`
(`ba2ffb4eb28a00ee945086b24f39bf639ca2250c`). UI-D0 adds the Docking workspace
shell, D2 adaptation/search-region transport, and renderer-neutral presentation
only. It does not add a docking engine or any D3 scientific execution.

## Changed-surface audit

The implementation surface is limited to:

- `apps/api/src/server.ts`: D2 adaptation and explicit SearchRegion sealing
  transport routes; existing capability truth continues to mark `DOCKING.RUN`
  unavailable.
- `apps/web/src/App.tsx`, `components/NavRail.tsx`, `domain/registry.ts`, and
  `styles/global.css`: first-class Docking workspace shell and navigation.
- `apps/web/src/docking/`: UI state, D2 adapter, input/state panels, workflow
  status, SearchRegion draft/commit form, and bottom supporting surfaces.
- `apps/web/src/components/MolecularCanvas.tsx` and
  `rendering/ThreeDMolViewerAdapter.ts`: one optional SearchRegion overlay path
  using the existing viewer.
- `apps/web/src/lib/apiClient.ts`: typed D2 transport methods.
- focused UI-D0 tests and the isolated Playwright config.

Inherited verification fixtures were regenerated by the test suite during the
run and then restored to the clean D2 baseline; they are not part of this
change set.

## Explicitly absent

- No scoring/search/optimization/pose generation.
- No worker, GPU, HTS, or native docking-engine integration.
- No fake jobs, scores, poses, events, or results.
- No new `JobStatus` values.
- No executable `DOCKING.RUN`; the accepted D2 reservation remains fail-closed.
- No second molecular viewer or alternate renderer.
- No camera-to-SearchRegion mutation path.

## Conclusion

UI-D0 is scope-clean for the accepted D2 boundary. Any later execution,
preflight, freeze, job, result, or scoring behavior requires a separate
accepted gate and must not be inferred from this shell.
