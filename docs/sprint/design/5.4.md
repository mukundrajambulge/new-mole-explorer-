# 5.4 Job runner in the API: final design

**Base: Design 2.** Design 2 brings the input security, provenance and stricter caps. From Design 1 we add the bootId and lock file, the real SIGKILL crash harness, the "write CANCELLED, then kill" order, and 409 on illegal transitions. The code was checked against Grep: `run.mjs` already calls `dock()` through the async `prep.mjs runProcess` with `signal` and `taskkill /T` (line 278). `spawnSync` is only used for the HOME lookup. So we run `runDockJob` in-process through `engineImpl` and `signal`, not as a child `node` process.

## Store decision
Use a file store built on the prepJobs patterns: UUID dirs, `writeAtomic` (retry on Windows rename EPERM), `confinedPath`, `scrubText`, a transition table, TTL and gc.
- **better-sqlite3:** rejected. It is a native addon, the host has no compiler, and no Node 24 win32 prebuild has been checked.
- **node:sqlite:** rejected. It works on 24.x but is still experimental: it prints a warning and its API can change.
- **Why files fit:** we only need get/list by id plus an append-only log. Files keep provenance next to the outputs and add no dependencies.
- **TOOLS.md:** gets a short note recording this decision.

## Files
- `apps/api/src/jobs/dockJobs.ts`: DockJobStore, FIFO queue, recovery, dedupe index.
- `apps/api/src/jobs/dockRunner.ts`: adapter over `runDockJob`. Holds the pidfile kill and the input resolution through PrepJobStore.
- `apps/api/src/jobs/dockJobs.test.ts`, plus `dockCrash.fixture.mjs` (a forked harness).
- `tools/mole-dock/run.mjs`: pidfile wrapper, async group kill, `onStage` progress hook.
- `packages/contracts/src/docking/jobs.ts`:
  - add `DockJobStateV1` (jobId, inputDigest, status, bootId, cancelRequested, progress, error, provenance, seq);
  - align caps with the stricter side: seed minimum 1 (contract allows 0, engine requires 1), box edge maximum 40 (engine allows 126).
- `apps/api/src/docking/routes.ts`: exports `createDockJobService(deps)` only. HTTP and SSE are task 5.5.

## Layout under root/<jobId>/
- `state.json` (DockJobStateV1, atomic)
- `job.json` (the zod-validated resolved request)
- `in/` (copied PDBQTs)
- `events.ndjson` (seq is monotonic, capped at 10000, a torn last line is dropped on read)
- `out/` (result.json, manifest)
- `pid` (WSL pgid)

`root/.lock` is created with O_EXCL and holds pid and bootId. A stale lock is taken over only if its pid is dead.

## Interface for 5.5
- `init()`
- `submit(req) -> {job, deduped}`
- `get(id)`
- `list()`
- `cancel(id)`
- `events(id, afterSeq)`
- `subscribe(id, cb) -> unsub`: replays from afterSeq, then attaches with no gap. Sequence: read the file, register the listener, re-read.
- `result(id)`: returned only when SUCCEEDED, zod-parsed, label `PREVIEW_UNQUALIFIED`, `meScore: null`.

Errors are `DockJobError(code, httpStatus)`, with no absolute paths:
- 400 BAD_INPUT
- 404
- 409 ILLEGAL_TRANSITION / ALREADY_TERMINAL
- 429 QUEUE_FULL
- 503 ENGINE_PIN_MISMATCH (nothing is queued)

## States
- QUEUED -> PREPARING | CANCELLED | FAILED
- PREPARING -> RUNNING | CANCELLED | FAILED
- RUNNING -> SUCCEEDED | CANCELLED | FAILED
- Terminal states have no outgoing moves.

Each change persists `state.json` first, then appends the event. Progress is reported only at real stage points (0, 0.05, 0.1, 1). No invented fractions.

## Submit and dedupe
1. The client sends prepared ids only. The server resolves them through PrepJobStore.
2. Seal must be SEALED or PREVIEW_UNQUALIFIED. BLOCKED or REJECTED returns 400.
3. Re-verify the manifest sha256, then copy the PDBQTs into `in/`.
4. cpu (at most 4) and timeout are fixed by the server.

`inputDigest` = sha256 of canonical JSON of {receptorSha, ligandSha, box, exhaustiveness, numPoses, seed, vinaPin}.

Locking: input resolution is the only async step. After it, lookup and insert in the `Map<digest, jobId>` happen synchronously (no await between them), so concurrent submits cannot race. The map is rebuilt in `init()`.

Reuse rules: a job that is QUEUED, PREPARING, RUNNING or SUCCEEDED (and not expired) is returned with `deduped: true`. FAILED or CANCELLED allows a new job.

Limits: one Vina at a time, queue max 8, at most 32 jobs and 2 GiB, retention 1 h for FAILED/CANCELLED and 24 h for SUCCEEDED. gc never touches live jobs.

## Runner and cancel (under 2 s)
- One loop takes the oldest QUEUED job.
- PREPARING: confine and hash `in/`, then check the Vina pin.
- RUNNING: `runDockJob({input, out}, {engineImpl, signal})`.

Launch inside WSL through a fixed wrapper, with positional args and no interpolation:
`/bin/sh -c 'echo $$ > "$1"; shift; exec setsid "$@"' sh <pidfile> /usr/bin/timeout -k 5 ...`

Cancel steps:
1. Set `cancelRequested` and write CANCELLED with its event.
2. `abort()`. runProcess then runs `taskkill /T /F` on wsl.exe.
3. Read the pidfile (must be digits only), then run `wsl.exe --exec /bin/kill -KILL -- -<pgid>`, asynchronously.

A late exit, including exit 0, after a terminal state is discarded. Cancelling a QUEUED job is a state change only and is idempotent.

Exit mapping:
- exit 0: re-read result.json and the manifest, zod-validate, re-hash poses and inputs, bind jobId and inputDigest, then SUCCEEDED.
- exit 2: FAILED BAD_INPUT
- exit 3: FAILED ENGINE

Provenance saved with the job: Vina version and sha, the TOOLS.md pin, input digests, seed, prepared ids, prep qualification.

## Crash recovery (`init()`)
- Each start gets a new bootId.
- PREPARING or RUNNING with a different bootId: best-effort kill of the pidfile pgid, then FAILED `API_RESTARTED` with a terminal event. Never resumed and never faked.
- QUEUED with intact `in/` hashes: requeued by createdAt. If `in/` is not intact: FAILED.
- Unparseable `state.json`: the dir is quarantined (renamed `.corrupt-<id>`) and left out of the list.
- Event seq continues from the last good line.

## Test plan (temp root, real tests/fixtures PDBQTs, fake engine that spawns a real long-running node process)
- **Cancel:** cancel while RUNNING gives CANCELLED and `process.kill(pid, 0)` throws ESRCH within 2000 ms. Cancelling a QUEUED job is immediate. Cancelling a terminal job returns 409. A late exit 0 is discarded.
- **Crash:** fork the harness, wait for RUNNING, SIGKILL the harness, then `init()` a new store on the same root. Expect:
  - the job is FAILED `API_RESTARTED`;
  - its child process is dead;
  - a QUEUED job resumes and succeeds;
  - seq stays monotonic;
  - the stale lock is taken over.
- **Dedupe:** `Promise.all` of two identical submits gives one jobId, one dir and one engine call. A different box gives two jobs. A resubmit after CANCELLED gives a new job.
- **Other:**
  - illegal transitions;
  - BLOCKED or unsealed ids rejected;
  - traversal ids rejected;
  - seed 0 and a box edge of 41 rejected;
  - queue full returns 429;
  - quota and gc spare live jobs;
  - event replay from afterSeq with a torn line;
  - results labeled `PREVIEW_UNQUALIFIED`, `meScore` null;
  - errors contain no absolute paths.
- **Optional:** a real Vina cancel smoke behind `--native`, checking with `pgrep` in WSL that no vina is left.

## Risks
- Vina left orphaned in WSL if wsl.exe dies before the pidfile is written. Mitigations: a short poll for the pidfile on cancel, and the coreutils timeout as a backstop.
- pid or pgid reuse after a reboot: kill only if `/proc/<pgid>/cmdline` contains the job's out-dir token.
- WSL cold start (more than 2 s) during PREPARING: a cancel there never needs WSL.
- SAFE_POSIX_PATH rejects roots that contain spaces: keep the job root under a fixed data dir without spaces.
- Windows rename EPERM: retry in writeAtomic.
- Out of scope: HTTP/SSE (5.5), concurrency above 1, resuming killed runs, ME scoring.
