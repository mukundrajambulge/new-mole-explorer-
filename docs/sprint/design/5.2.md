# Design 5.2: Preparation worker (final note)

**Base: Design 1.** It uses a one-shot deterministic CLI with no server or queue, which is the smaller and more testable path. Grafted from Design 2: plan and apply as two separate steps, server-held artifact ids, box seal from `jobId` only, startup pin check, a small state machine, and the GENERATED_PROFILE conflict (confirmed in `d2Preparation.ts:78-83`).

## Principle
The worker is `python -I` run as a one-shot CLI with two modes, `--plan` and `--apply`. It never seals anything. The API spawns it, reads one manifest, recomputes every hash, and seals using existing D2 functions. The client never supplies chemistry, sha256 values or profile digests. Supplying a client sha256 gives SECURITY_REJECTION.

## Files (owned)
1. `workers/prep/mole_prep/{cli,receptor,ligand,manifest,limits}.py`
   - `--plan` writes `plan.json`: every choice (model, chain, altloc, waters/hetero list, pH, protonation source, tautomer, charge model, torsions) with before/after atom counts. It does not modify the structure.
   - `--apply` runs only the confirmed choices. Pipeline: PDBFixer, then PDB2PQR+PROPKA, then RDKit (explicit bond orders required, otherwise BLOCKED), then Meeko 0.8.0. It writes pdbqt files, cleaned pdb/sdf, canonical atom/bond JSON, and `prep-manifest.json`.
   - Determinism: PYTHONHASHSEED=0, one thread, fixed seeds, canonical atom order, no timestamps or absolute paths.
   - Each stage records `{tool, version, params, inSha, outSha, decisions[]}`. The worker revalidates its input and rejects NaN/Inf.
2. `workers/prep/tests/{test_prep_pairs.py,pairs.json}`: 10 real pairs plus negative cases.
3. `tools/mole-dock/prep.mjs`: the only spawn path. It uses an argv array (no shell), a fixed interpreter via `wsl.exe`, a scrubbed env, cwd set to the job dir, a 120 s per-stage timeout, process-group kill, and capped, path-scrubbed stderr.
4. `packages/contracts/src/docking/jobs.ts` (exported from the index):
   - zod `PrepPlanV1`
   - `PrepConfirmationV1{jobId, planDigest, acks[]}`
   - `PrepManifestV1{stages, outputs[{role, relPath, sha256, bytes}], status PREPARED|BLOCKED, diagnostics}`
   - `PrepJobStateV1`
   - Size caps on all of the above.
   - `planDigest = sha256(canonical plan JSON || lock digest)`.
5. `apps/api/src/jobs/prepJobs.ts`:
   - UUID job dirs under the project root, atomic writes.
   - States: AWAITING_CONFIRMATION, APPLYING, SUCCEEDED, FAILED, EXPIRED, with one transition table.
   - One concurrent job, 30 min TTL.
   - On restart, in-flight jobs become FAILED.
6. `apps/api/src/jobs/prepSeal.ts`: `sealFromPrepManifest(jobId)`.
   - Re-hashes every output and rejects any mismatch.
   - Maps the canonical JSON into D2 adapter inputs, then calls the existing `sealPreparedReceptorState`, ligand and kinematic seals.
   - Profile digests come only from server constants in `profiles.ts`.
7. `apps/api/src/docking/routes.ts`:
   - `POST /docking/prep/plan {receptorArtifactId, ligandArtifactId, pH, ...}`
   - `POST /docking/prep/:id/confirm` returns 409 on digest mismatch. Confirmation is single-use.
   - `GET /docking/prep/:id`
   - All routes use zod, a body cap, root-confined paths and relative-only errors. `DOCKING.RUN` stays fail-closed.
8. `native/third_party/TOOLS.md`: add rows for the entry point, seed, lock digest and prep profile ID only.

**outsideOwnedFiles:**
- `scripts/sprint/check.mjs`: hook the pairs test into `--python`.
- The 4.4 box-seal call site: it must take `{jobId, bounds | referenceLigand}` only.

## Interfaces
- **Uploads:** the server stores uploads by a sha256 it computes itself. The client sends only artifact ids.
- **Startup pin check:** compares the lock hash, tool versions and vina sha256 against TOOLS.md. Any mismatch fails closed (PROVENANCE_REPLAY).
- **Box seal (4.4):** reads the receptor/ligand digests from the stored SUCCEEDED job. It never accepts a digest from the request.

## Test plan
- **Python, done-when:** 10 pairs from `tests/fixtures`.
  - Receptors: 1CRN, 1HZH, 1D3Z, 4DJW, 5FYL.
  - Ligands: ethanol.sdf, ring-ligand.pdb, g1c-small-molecule.pdb, plus HETATM ligands cut from those RCSB files.
  - Each pair runs plan, then apply, twice in different temp dirs. Every output must be byte-identical by sha256.
- **Python, negative:** g1c-malformed.pdb gives BLOCKED. Also tested: an unsupported element, an oversize input, a missing bond orders case, and NaN coordinates.
- **API:**
  - forged or stale planDigest gives 409
  - a reused confirmation is rejected
  - a tampered output or manifest is rejected
  - path traversal in artifact id or relPath is rejected
  - an oversize body is rejected
  - a client sha256 on the box seal gives SECURITY_REJECTION
  - a timeout or crash gives FAILED, scrubbed
  - a lock or vina mismatch fails closed
  - sealing from real fixture output works
- **Contracts:** zod round-trip tests and cap tests.

## Risks
- **Protonation is blocked by D2 core today (owner decision).** PDB2PQR/PROPKA output is `GENERATED_PROFILE`, and D2 core rejects that (`UNSUPPORTED_AUTOMATIC_PROTONATION`).
  - Default: keep the submitted hydrogens (`EXPLICIT_SUBMITTED`). Expose PROPKA as an opt-in choice that seals as PREVIEW_UNQUALIFIED until a qualified profile exists.
  - Constraint: do not add a profile ID or digest without owner approval.
- **The manifest may not map 1:1 to the D2 seal inputs.** atomTyping needs evidenceRef and chargeModel. The adapter must emit them, otherwise the seal result is BLOCKED. Never fill in placeholders.
- **The toolchain runs only in WSL.** CI reports SKIPPED, never pass. Byte identity is guaranteed only within the pinned environment; floats may differ on other machines.
- **Size limits:** exclude 6VXX/4V6F. Enforce D2_LIMITS plus 20 MB, 200k receptor atoms and 5k ligand atoms.
- **Licensing:** Meeko (LGPL) and OpenMM stay in a separate process only.
- **Not included:** queue, retries and cancel-by-API. One-shot jobs with a TTL are enough for 5.2.
